# Alpha limitations

Applies to: `1.0.0-alpha.1`

Last reviewed: 21 October 2026

Alpha means controlled early use and continued validation. It does not imply general availability, a successful teacher study or release approval.

- Supported formats differ. A source-specific exercise excerpt is not a universal full-paper editor.
- Some complete-paper and blueprint tools are development-only. Hosted availability must be checked on the exact deployed build.
- An imported or approved inventory count is not proof of adequate usable supply, valid replacements or complete curriculum coverage.
- The current hosted candidate browses Units 1–4 but its available generation paths remain Unit 1. Its standalone preset pool is empty; six complete MCQ exercises are eligible. Read the dated [content/builders audit](alpha-content-and-builder-coverage-2026-10-21.md) before choosing a brief.
- Difficulty metadata is not proof of calibrated educational difficulty.
- Arbitrary PDF, Word and image extraction is not promised by the supported CSV/interchange workflow.
- Browser page estimates do not guarantee identical Word/LibreOffice pagination. Changed document pairs need their own required visual acceptance.
- Saving, finalization and history differ by workflow. Do not treat a simple draft as an immutable structured snapshot.
- Connection-loss recovery is bounded. Do not assume full offline editing, synchronization or guaranteed remote saving.
- A successful browser download request does not prove both files arrived or opened correctly.
- A private text-feedback report can describe a teacher's experience and accompany exact files; it does not independently verify the actions, timings or help used. Artifact review and the original observed-workflow gates remain separate.

On 20 October 2026, Linear MIN-20 records Phase 16 Alpha preparation in progress with observed teacher success gates still open. This is a dated observation, not a copied task board. Read [the live issue](https://linear.app/minego/issue/MIN-20/phase-16-private-teacher-alpha) for current status.

The current version label is assigned to the working checkout. Existing hosted artifacts keep their own revisions and verification scope until an explicitly authorized new deployment. Stable release and Production actions remain gated separately.
