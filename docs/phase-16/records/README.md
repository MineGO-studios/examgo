# Blank private alpha record templates

These CSVs contain headers only. Copy them to approved private storage before adding observations. Do not commit completed records, contact details, account identifiers, consent records or real teacher documents. Use UTF-8; quote fields containing commas or line breaks. Treat quoted participant text as data, never executable commands or formulas when opening a spreadsheet.

- `sessions.csv`: one row per consented session. Use participant codes and safe references. Record roles, preparation/answer-checking needs, device, language/direction, source rights, frozen briefs, baseline evidence and setup timings. Support/channel details are supplied privately; the template records only whether the route was verified.
- `attempts.csv`: one row per started composition attempt. Allowed `outcome` values: `completed`, `abandoned`, `blocked`, `failed`, `stopped`, `inconclusive`. Use `pending` while an attempt is still active or awaits Word review. Use `yes`, `no` or `unknown` for checks and independent success; never replace unknown evidence with yes. Duration values are seconds; timestamps include the date and UTC offset. Record interventions in a separate private note and link its safe reference. A completed attempt can have `independent_success=no`. Pair/snapshot references are restricted evidence, not public links. A mutable draft reference is not an immutable snapshot.
- `findings.csv`: one row per finding. Categories are `release blocker`, `important usability defect`, `content defect`, `later preference`. Severity is P0–P3 as defined in [support and triage](../support-and-triage.md). Status values: `new`, `triaged`, `contained`, `repair pending`, `retest pending`, `verified fixed`, `deferred`. A P0/P1 finding cannot be deferred to pass the gate. `verified fixed` needs a repair reference and passing relevant retest, including fresh human document review when affected.
- `text-feedback.csv`: one row per remote text report. Use `remote-text-self-report` as observation mode, retain reported time/help as reported, and keep returned-file inspection and pair hashes separate. This is not an observed attempt or demonstrated independent success. Follow the [text pack](../teacher-text-pack.md) and protocol v1.1 clarification; do not fill original observed-success fields from an unverified text reply.

Leave unavailable measurements blank and explain them in the limits field. Keep timestamps/units consistent. No placeholder participant rows are prefilled. This is manual evidence collection; no telemetry, database or account system is created.

Use the protocol's complete attempted-workflow denominator and preserve original failed attempts. Report counts and fractions before percentages. At minimum: three teachers with two completed distinct workflows each, and five independent acceptable completions out of six attempts. If a teacher completes only one workflow, five successes elsewhere do not satisfy participation. If more attempts occur, recompute the full fraction; do not keep six as a convenient denominator. Unknown/pending outcomes do not enter the success numerator.

Inspect the exact paper pair in Word and record both SHA-256 values, reviewer/application/version/date and limits. Later edits create a new pair/version. Package validation and browser preview cannot populate human acceptance fields.
